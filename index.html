업무 매뉴얼

업무를 선택해 순서와 확인할 내용을 보세요.

온라인 주문 확인하나로·롯데 매출 입력신규 상품 등록할인 변경·가격택현수막·인쇄물 제작명함·연락처 정리카탈로그·사업계획서 수정과거 제작 건별도 참고
01온라인 주문 확인＋

언제: 매일.

준비물: 카페24·네이버·이카운트 주문 화면.

  1. 카페24·네이버·이카운트에서 새 주문과 미처리 주문을 확인합니다.
  2. 상품·색상·사이즈·수량·결제 상태를 대조합니다.
  3. 재고와 취소·변경 요청을 확인합니다. 처리 기준이 불명확하면 담당자에게 확인합니다.

완료 확인: 주문 확인과 출고 완료를 구분해 기록합니다.

확인 필요: 주문 마감 시각, 출고 담당자, 품절·취소 처리 기준.

02하나로·롯데 매출 입력＋

언제: 반복 업무. 금·토·일분은 월요일에 날짜별로 모아 처리합니다.

준비물: 하나로 3계정, 롯데 조회 화면, 최신 매출장.

  1. 계정과 조회 날짜를 확인합니다. 하루 조회는 시작일과 종료일을 같게 설정합니다.
  2. 날짜·매장별 금액을 기존 매출장과 대조합니다.
  3. 누락분만 입력합니다. 기존 값과 다르면 덮어쓰지 말고 원자료를 확인합니다.
  4. 새로 입력한 셀에만 밑줄을 적용하고 기존 수식·서식은 유지합니다.
  5. 저장 후 다시 열어 날짜·매장·금액을 대조합니다.

확인 필요: 목요일 매출을 금요일에 처리할지 월요일에 처리할지는 미확정입니다. 날짜·매장명이 불명확한 자료도 확인 후 입력합니다.

표시 규칙: 추가 강조색은 해당 작업의 지시를 따릅니다.

03신규 상품 등록＋

언제: 새 상품이 있을 때.

준비물: 실물 상품, 기존 사진 또는 촬영 원본, 상품정보.

  1. 전무님께 기존 실착 사진을 확인합니다. 없으면 촬영합니다.
  2. 상품별 사이즈를 측정하고 단위와 단면 여부를 기록합니다.
  3. 원본을 보존하고 사진 보정·필요한 AI 모델컷을 제작합니다.
  4. 실제 옷과 색·무늬·길이·디테일을 대조합니다.
  5. 확인된 상품정보와 사진을 등록하고 모바일 상품 화면을 확인합니다.

완료 확인: 이미지 제작 완료와 실제 상품 등록 완료를 구분합니다.

확인 필요: 이미지 규격, 필수 입력 항목, 가격·재고 확인 담당자.

자세히: 품목별 실측 기준은 별도 참고로 분리합니다. 회사 기준이 없는 측정 위치·허용 오차는 정하지 않습니다.

04할인 변경·가격택＋

언제: 주간 할인 또는 가격택 요청 시.

준비물: 대상 상품 목록, 승인된 가격, 기존 가격택 템플릿.

먼저 확인: 최초 지시는 “화요일 30%-50% 가격세일”, 저장본 본문은 “30%→50%”, 수기 메모는 “월요일/화요일만 50%→30%”로 서로 다릅니다. 적용 요일·대상 상품·할인 방향을 확인한 뒤 변경합니다.

  1. 대상 상품과 할인 전 가격, 적용·종료 시각을 확인합니다.
  2. 변경 후 실제 상품 화면의 가격과 중복 할인 여부를 대조합니다.
  3. 가격택은 기존 템플릿에서 필요한 정보만 수정합니다.
  4. 실제 크기로 시험 출력한 뒤 요청 수량을 제작합니다.

예외: 잠옷은 택을 변경하지 않는다는 기존 메모가 있습니다.

완료 확인: 실제 상품 화면과 가격택의 금액이 승인된 가격과 일치하는지 확인합니다.

05현수막·인쇄물 제작＋

언제: 제작 요청 시.

준비물: 기존 디자인, 크기·문구·수량·납기와 예산.

  1. 사장님께 크기와 내용을 먼저 확인합니다. 가로·세로·단위, 넣을 문구·뺄 문구를 적습니다.
  2. 수량·납기·예산과 주문 업체·계정을 확인합니다.
  3. 원본을 복사해 수정하고 문구·숫자·브랜드 표기·QR 연결을 검수합니다.
  4. 시안을 확인받고 타공·마감·배송비를 포함한 총액을 대조합니다.
  5. 승인 파일로 주문한 뒤 주문번호·입금 안내·수령일을 전달합니다.

완료 확인: 시안 승인, 주문 접수, 입금, 수령은 별도 상태로 기록합니다.

06명함·연락처 정리＋

언제: 완료할 때까지 매일. 새 명함을 받으면 다시 매일 처리합니다.

준비물: 원본 명함과 최신 연락처 파일.

  1. 앞·뒷면을 확인해 이름·직함·소속·전화·이메일을 옮깁니다.
  2. 기존 연락처에서 이름과 번호·소속을 함께 검색합니다.
  3. 중복을 제외하고 새 정보만 최신 파일에 추가합니다. 판독 안 되는 글자는 추측하지 않습니다.
  4. 원본과 대조하고 저장 결과를 확인합니다.

주의: 동명이인을 합치거나 변경된 연락처를 확인 없이 삭제하지 않습니다.

완료 확인: 새 정보와 원본을 대조하고 저장 여부를 확인합니다.

07카탈로그·사업계획서 수정＋

언제: 회사 정보 변경 시.

준비물: 최신 원본과 회사에서 확인한 변경 정보.

대상: 공유파일 '9.사업계획서(SS,FW)카다로그'.

  1. 수정할 시즌·최신 원본과 회사가 제공한 연락처·주소·사업자등록증을 확인합니다.
  2. 사본에서 해당 정보만 수정합니다.
  3. 표지·본문·연락처 페이지·첨부자료에 옛 정보가 남았는지 확인합니다.
  4. 최종 전달본에서 잘림과 링크를 확인하고 파일명·저장 위치를 전달합니다.

완료 확인: 변경된 정보가 모든 대상 페이지와 전달본에 반영됐는지 확인합니다.

01시작할 때

읽는 법: 회사 자료에 나온 지시와 아래의 일반 실행 예시를 구분하세요. 예시는 일을 빠뜨리지 않도록 돕는 방법이며 회사의 확정 정책·메뉴·치수 기준을 새로 정한 것이 아닙니다.

권장 순서: ① 오늘 주문·매출 확인 → ② 마감 있는 제작·등록 → ③ 명함·자료 정리. 실제 마감이 있으면 먼저 처리합니다.

지시를 받을 때는 무엇을 / 언제까지 / 몇 개 / 어느 파일에 / 누구 확인을 받고 할지 적습니다. 모르는 내용은 그 자리에서 “제가 이렇게 하면 될까요?” 하고 읽어 확인합니다. 녹음은 보조 기록이며 기억이나 추측으로 빈칸을 채우지 않습니다.

실제로 적는 업무 메모

아래 양식은 제안 예시입니다. 종이나 업무 메모에 한 건씩 적으세요.
업무명: ___ / 요청자: ___ / 마감: ___ / 원본 파일: ___
바꿀 것: ___ / 그대로 둘 것: ___ / 필요한 수량: ___
완료 확인할 사람: ___ / 아직 모르는 것: ___

지시를 받은 직후

1. 요청을 들으면서 숫자·날짜·파일명을 먼저 적습니다. ‘빨리’는 날짜가 아니므로 필요한 시점을 묻습니다.

2. ‘A는 바꾸고 B는 유지해서, ○일까지 이 파일로 보여드리면 될까요?’라고 읽어 확인합니다.

3. 중간 시안과 최종본을 다른 이름으로 보관하고, 승인받은 판본을 메모에 표시합니다.

4. 막히면 현재 파일과 막힌 화면을 함께 보여주고 한 가지 결정만 묻습니다.

완료 예시: ‘만들었음’ 대신 ‘수정본 저장 → 요청자가 문구 확인 → 최종 파일 확정’까지 구분합니다.

02온라인 주문 확인

주기: 매일.

1. 카페24와 네이버의 온라인 주문 유무를 각각 확인합니다.

2. 새 주문이 있으면 해당 주문의 상품·수량·처리 상태를 확인하고 회사의 출고 절차로 연결합니다.

3. ‘주문 확인’과 ‘출고 완료’를 구분해 기록합니다.

확인 필요: 주문 조회의 실제 메뉴, 출고 담당자, 주문 마감 시각, 취소·품절 처리 기준. 현재 확인된 자료만으로 택배 접수나 환불을 자동 처리하지 않습니다.

출처: 회사 매일 체크리스트 (내부 확인 자료).

주문 화면에서 실제로 볼 것

아래는 공통 주문 점검 예시이며 회사 관리자 화면의 정확한 메뉴명은 미확정입니다. 카페24·네이버에서 각각 주문 관리 화면을 열고, 조회 기간·상태 필터를 먼저 확인하세요. 전날 건만 보다가 이전 미처리 주문을 놓치지 않도록 미처리 상태도 별도로 확인합니다.

1. 주문번호와 주문일을 확인해 이미 처리한 주문인지 대조합니다.

2. 상품명뿐 아니라 색상·사이즈·옵션·수량을 함께 봅니다. 예: ‘니트 1개’가 아니라 ‘니트 / 베이지 / M / 1개’.

3. 결제 상태, 취소·변경 요청, 재고·품절 여부를 확인합니다. 결제 대기와 결제 완료를 혼동하지 않습니다.

4. 출고 가능 여부와 담당자에게 넘길 내용을 정리합니다. 배송지 변경은 원 주문과 최신 요청을 대조하고 임의 수정하지 않습니다.

5. 송장 등록이나 발송 처리는 실제 택배 인계 여부를 확인한 뒤 회사 기준대로 합니다.

막힐 때 묻기: ‘이 옵션은 재고가 없는데 대체 제안과 취소 중 어떤 방식으로 안내할까요?’
완료 기준: 조회만 했으면 ‘주문 확인’. 실제 출고·송장 반영까지 확인된 건만 ‘출고 완료’. 고객 주소·전화번호는 이 사이트에 기록하지 않습니다.

03하나로와 롯데 매출

주기: 매일, 전날까지 미조회·미입력분 확인.

1. 하나로 3계정과 롯데의 날짜별·매장별 판매금액을 확인합니다. 하루 조회는 시작일과 종료일을 같은 날짜로 설정합니다.

2. 기존 매출장의 날짜·매장·금액과 대조해 이미 입력된 항목을 제외합니다.

3. 확인한 누락분만 입력하고 새로 입력한 셀에만 밑줄을 적용합니다.

4. 조회 근거와 입력 결과를 대조합니다. 날짜가 안 보이는 캡처는 날짜 확인 전 확정 자료로 취급하지 않습니다.

수동 업무와 자동화는 별개입니다. 매출 자동화는 사용자 보류 상태로 다루며, n8n 인수인계서가 있다는 이유로 연결·실행을 재개하지 않습니다. 실제 조회 → 사본 입력 → 독립 검수까지 확인되어야 자동화가 완료된 것입니다.

출처: 회사 매출 항목 (내부 확인 자료) · n8n 인수인계서 (내부 자료).

입력하기 전에 파일과 날짜 맞추기

아래는 기존 중복 방지·밑줄 규칙을 실행하는 점검 예시입니다. 조회 자료와 매출장을 나란히 열고, 파일명·시트명·입력할 날짜·매장명부터 맞춥니다. 원본에 바로 덮어쓰지 말고 회사에서 정한 검수용 사본이 있으면 그 사본을 사용합니다.

1. 조회 화면에서 선택된 계정, 시작일·종료일, 매장별 행과 합계 행을 확인합니다. 매장별 입력 시 합계 행을 한 매장처럼 중복 입력하지 않습니다.

2. 매출장에서 해당 날짜·매장 셀을 찾습니다. 이름이 줄여져 있거나 다른 표기이면 기존 동일 매장 사례로 대조하고, 추측해서 다른 매장에 넣지 않습니다.

3. 이미 금액이 있으면 새 값으로 덮지 말고 원자료와 차이를 확인합니다. ‘빈칸’, ‘0원’, ‘조회 안 됨’은 서로 다릅니다.

4. 새로 입력한 값만 밑줄을 적용합니다. 과거 셀·수식·서식은 불필요하게 바꾸지 않습니다.

5. 날짜·매장별 값을 다시 대조하고 새 입력 합계가 조회 근거와 맞는지 확인합니다. 저장 후 파일을 다시 열어 입력이 남았는지 봅니다.

숫자 예시: A매장 120,000원 + B매장 80,000원 = 200,000원. 이 수치는 연습용이며 실제 매출이 아닙니다.
확인 질문: ‘이 캡처는 어느 날짜인가요? 이 매장명이 매출장의 어느 시트와 연결되나요?’
중단 조건: 날짜 불명, 매장 연결 불명, 기존 값과 충돌, 수식 오류. 해당 셀을 추정 입력하지 않고 근거와 차이만 남깁니다.

04상품 사진과 신규 상품 등록

주기: 새 상품이 생길 때.

1. 전무님께 기존 실착 사진이 있는지 묻습니다. 있으면 전달받고, 없으면 실착 사진을 촬영합니다.

2. 의상 사이즈를 측정합니다.

3. 사진을 개별 보정한 뒤 필요한 모델컷을 생성합니다.

4. 상품 사진과 상품 정보를 준비한 후 쇼핑몰에 등록합니다.

5. 시안 검수와 실제 상품 등록 완료를 따로 확인합니다.

검수 항목: 실제 옷의 색·무늬·형태가 달라지지 않았는지, 포즈·배경이 기존 상품 목록과 어울리는지.

확인 필요: 상품별 필수 입력 항목, 이미지 규격, 가격·재고 최종 확인 담당자. 확인되지 않은 상품 정보를 만들어 넣지 않습니다.

출처: 최우선 과제 (내부 확인 자료) · 상품 목록 예시 ↗.

측정 준비와 기록 방식

아래 측정법은 일반적인 의류 실측 예시이며 칼리베이직의 확정 측정 규정은 아닙니다. 회사 기존 상품표와 측정 시작점을 먼저 맞추세요. 단위는 cm로 통일해 기록하고, 상품코드·색상·사이즈·측정일을 함께 적습니다.

1. 평평한 테이블에 옷을 놓고 단추·지퍼를 자연스럽게 잠급니다. 앞뒤 옷감과 봉제선을 정리하되 니트·밴딩을 잡아당기지 않습니다.

2. 줄자를 비틀거나 공중에 띄우지 말고 옷 위에 놓습니다. 시작점과 끝점을 사진으로 남기면 다음 측정 때 같은 기준을 쓸 수 있습니다.

3. 같은 위치를 다시 재어 값이 다르면 주름·시작점·줄자의 기울기를 확인합니다.

4. ‘단면’은 평평하게 놓은 한쪽 폭입니다. 가슴단면 50cm는 단순 환산 둘레 약 100cm이지만 인체 가슴둘레나 권장 착용치수와 같다는 뜻은 아닙니다. 상품표가 단면이면 50으로 적고 임의로 100으로 바꾸지 않습니다.

상의와 재킷은 어디를 재나요

• 어깨너비: 등 쪽에서 왼쪽 어깨 봉제선 끝부터 오른쪽 끝까지 직선. 드롭숄더는 실제 봉제선 위치를 기준으로 표기합니다.

• 가슴단면: 양쪽 겨드랑이 아래의 같은 높이를 가로로 잽니다. 겨드랑이 바로 아래인지 몇 cm 아래인지는 기존 회사 기준 확인이 필요합니다.

• 소매길이: 어깨 봉제선에서 소매 끝까지. 래글런은 어깨선이 없으므로 목 옆 또는 뒤 중심에서 잰 길이인지 기준을 별도로 표시합니다.

• 총장: 목 옆 어깨의 높은 지점부터 밑단까지, 또는 뒤목 중심부터 밑단까지 중 기존 표 기준을 사용합니다. 두 방식을 섞지 않습니다. 앞뒤 길이가 다르면 각각 적습니다.

• 소매통·소매끝·밑단단면: 회사 상품표에 있으면 팔의 지정 높이·소매 끝·몸판 밑단을 가로로 잽니다.

바지는 어디를 재나요

• 허리단면: 단추·지퍼를 잠근 허리밴드를 정리해 좌우 끝을 잽니다. 곡선 허리밴드는 직선/곡선 측정 기준을 확인합니다.

• 엉덩이단면: 엉덩이의 가장 넓은 부분을 수평으로 잽니다. 허리에서 몇 cm 아래인지 지정 규정이 있으면 그 위치를 사용합니다.

• 앞밑위: 앞 허리 위끝에서 가랑이 봉제선 교차점까지 앞 중심 봉제선을 따라 잽니다. 허리밴드 포함 여부를 표시합니다. 뒷밑위는 뒤 중심으로 별도 측정합니다.

• 허벅지단면: 가랑이 바로 아래의 한쪽 다리를 가로로 잽니다. ‘가랑이에서 몇 cm 아래’ 기준이 있으면 그 기준을 기록합니다.

• 밑단단면: 한쪽 바지 끝의 좌우 폭.

• 인심: 가랑이 봉제선 교차점부터 안쪽 다리 봉제선을 따라 밑단까지.

• 총장: 허리 위끝부터 바깥 옆선을 따라 밑단까지. 인심과 총장을 바꾸어 적지 않습니다.

치마와 원피스와 세트

• 치마: 허리단면·엉덩이단면·총장을 기본 확인합니다. 총장은 허리 위끝부터 밑단까지. 플레어 치마의 엉덩이 측정 위치는 회사 기준을 확인합니다.

• 원피스: 어깨·가슴·허리·엉덩이·소매·총장 중 디자인에 해당하는 항목을 잽니다. 허리선이 없으면 임의의 가장 잘록한 위치를 회사 기준처럼 쓰지 않습니다.

• 세트·잠옷: 상의와 하의를 별도 기록합니다. 한 벌의 사이즈 하나로 두 옷의 치수를 대신하지 않습니다.

• 밴딩: 힘을 주지 않은 허리단면과 늘린 값을 구분합니다. ‘최대 늘림’은 당기는 힘에 따라 달라지므로 회사 방식 확인 전 억지로 늘려 재지 않습니다.

• 니트·신축성 있는 옷: 자연스럽게 놓은 값과 신축성 설명을 구분합니다. 사이즈별 실물 없이 치수를 일정 폭씩 추정해 채우지 않습니다.

사진 촬영부터 등록까지 구체 순서

일반 촬영·등록 점검 예시입니다. ① 상품코드별 폴더를 만들고 원본 보관 → ② 정면·뒷면·디테일·라벨·실측 근거 촬영 → ③ 흐림·색 왜곡 확인 → ④ 복사본에서 배경·주름 보정 → ⑤ 실제 옷의 색·무늬·길이·단추 수 대조 → ⑥ 상품명·색상·사이즈·소재·세탁정보·가격·재고를 근거로 입력 → ⑦ 모바일 미리보기 → ⑧ 게시 승인·실제 반영 확인.

기록 예시: ‘상품 A / M / 가슴단면 50cm / 총장 62cm / 목 옆 어깨부터 측정’. 숫자는 예시입니다.
사장님께 확인: ‘기존 표는 총장을 어디서부터 재나요? 가슴은 겨드랑이 아래 어느 위치인가요? 실측 오차 문구는 회사에서 쓰는 문구가 있나요?’ 임의로 ‘1~3cm 오차’를 회사 규정처럼 넣지 않습니다.

측정 참고 원문: Proper Cloth 셔츠 가슴너비 측정 ↗은 주름을 펴고 양쪽 겨드랑이 아래를 직선으로 재는 방법을 설명합니다. 이 글의 장점인 준비 상태·시작점·끝점 분리를 적용했습니다. 해당 업체의 허용 오차나 다른 품목 규칙을 칼리베이직 기준으로 가져오지는 않았습니다.

05할인 변경과 가격택

주기: 주간 할인 작업 및 가격택 필요 시.

- 현재 회사 목록의 할인 변경 지시는 30%→50%입니다. 할인 대상 상품과 적용 시작·종료 시각을 확인한 후 변경합니다.

- 요일은 원문에 ‘매주 (월)화요일’로 남아 있습니다. 2026년 11월 16일은 월요일, 17일은 화요일이므로 다음 작업일을 임의로 확정하지 않습니다.

- 반값세일 가격택 50개는 현재 회사 목록에서 완료 체크되어 있습니다. 새 수량 요청 없이 다시 만들지 않습니다.

- 원문 메모: 잠옷은 택을 변경하지 않음. 다른 제품은 기본적으로 회사 택이 들어가 있음.

확인 필요: 정확한 주간 작업일, 대상 상품, 가격택 추가 수량. 현수막의 ‘50% 삭제’ 지시는 아래 별도 제작 건의 조건이며 상품 할인 규칙과 섞지 않습니다.

출처: 회사 주간 할인 및 가격택 기록 (내부 확인 자료).

가격을 바꾸기 전후

아래는 실행 전 대조 예시입니다. ① 할인 대상 상품 목록·현재 가격을 보관 → ② 할인 기준 가격과 적용 시각 확인 → ③ 변경 후 실제 판매가 계산 대조 → ④ 쿠폰·다른 할인 중복 여부 확인 → ⑤ 대표 상품을 PC·모바일에서 확인 → ⑥ 종료일에 원복할 기준을 기록합니다.

계산 예시: 정가 50,000원의 30% 할인가는 35,000원, 50% 할인가는 25,000원입니다. 35,000원에서 다시 50% 할인하면 17,500원이므로 ‘정가 기준 50%’와 다릅니다. 실제 회사 할인 기준을 확인하고 적용합니다.

가격택 제작 예시

상품명·옵션·원가 아닌 표시 기준가격·판매가·할인율을 확인한 뒤 기존 가격택 템플릿의 해당 칸만 바꿉니다. 파일에서 맞아 보여도 실제 크기로 시험 출력해 잘림·가독성·앞뒤 배치를 확인한 뒤 필요한 수량을 출력합니다. 50개 완료 건은 반복 출력하지 않습니다.

확인 질문: ‘50%는 정가 기준인가요? 예외 상품이 있나요? 홈페이지와 가격택을 동시에 바꾸나요?’
완료 기준: 관리자 값 저장뿐 아니라 실제 상품 화면과 출력된 가격택의 금액이 일치하는지 확인합니다.

06현수막과 인쇄 제작

주기: 제작 요청을 받을 때.

1. 가로·세로·단위, 넣을 문구와 뺄 문구, 수량·납기·비용 한도를 적고 확인합니다.

2. 기존 디자인·주문 내역과 대조하고 브랜드 표기·숫자·오탈자를 검수합니다.

3. 재단 여유·마감·타공과 추가 비용을 업체에 확인합니다.

4. 시안을 확인받고 원본은 보존한 채 날짜·판본을 넣어 다른 이름으로 저장합니다.

5. 승인 파일과 주문 조건을 마지막으로 대조합니다. 주문 후에는 주문번호·입금 안내·담당자·납기를 인계하며, 입금 안내 전달과 결제 완료를 구분합니다.

한 장짜리 현수막 체크매뉴얼 PDF (내부 자료) · 편집 가능한 원문 (내부 자료)

11월 12일 제작 건에만 적용

- 기존 핑크 디자인 활용, 50% 문구 삭제. 30%로 임의 변경하지 않습니다.

- 양쪽 구멍은 추가금이 없을 때만 적용하는 조건입니다.

- 녹음 전사의 ‘500에 90’은 단위 미확인입니다. 원본 주문·업체 규격으로 확인합니다.

- 20장과 가격 언급은 최종 확정값으로 취급하지 않습니다. 납기는 ‘최대한 빨리’로만 확인됩니다.

- ‘1위 선정’ 문구와 브랜드 정식 표기는 원자료·승인 시안 확인이 필요합니다.

- 회사 할 일 목록에는 카카오톡 친구추가·홈페이지 QR 추가가 남아 있습니다. 최신 승인 시안과 대조한 뒤 적용합니다.

출처: 현수막 대화 (내부 자료), 녹음 두 개의 추출 전사와 현아의 정정을 정리한 체크매뉴얼. 원음 직접 청취·초 단위 대조는 미완료입니다.

파일에서 무엇을 확인하나요

일반 제작 검수 예시입니다. 기존 원본을 복사한 뒤 ① 문서 가로·세로와 단위 ② 넣을 문구·뺄 문구 ③ 로고·브랜드 표기 ④ 재단선 근처 글자 ⑤ QR 두 종류의 목적지를 순서대로 확인합니다. 화면 배율과 실제 인쇄 크기를 혼동하지 않습니다.

QR 확인: 휴대폰으로 카카오톡 QR과 홈페이지 QR을 각각 스캔해 예상한 채널·페이지로 열리는지 확인합니다. 두 QR이 뒤바뀌거나 이미지가 흐리면 주문하지 않습니다. 인쇄 크기에서 실제 스캔도 시험합니다.

업체에 묻는 문장

‘가로 ___, 세로 ___, 단위 ___이고 ___장입니다. 재단 여유는 얼마를 넣나요? 타공은 추가금이 없을 때만 원합니다. 총액과 배송비, 최종 수령 가능한 날짜를 알려주세요.’ 회사의 예산·발주 권한을 확인하기 전에는 주문 확정이나 입금을 약속하지 않습니다.

07명함과 연락처

주기: 새 명함을 받을 때.

1. 전무님께 받은 명함을 기존 연락처 자료와 대조합니다.

2. 이름·소속·연락처가 같은 기존 항목이 있는지 확인합니다. 불분명하면 같은 사람이라고 단정하거나 삭제하지 않습니다.

3. 새로 확인된 정보만 정리하고 원본 명함은 보존합니다.

4. 추가한 항목과 확인이 필요한 항목을 구분합니다.

현재 할 일: 전무님께 받은 명함 업로드. 기존 연락처 후속 정리의 완료 체크를 새 명함 처리 완료로 해석하지 않습니다.

확인 필요: 실제 최신 연락처 파일과 업로드 위치. 연락처 실데이터는 이 매뉴얼에 복제하지 않습니다.

출처: 명함 및 연락처 기록 (내부 확인 자료).

명함 한 장을 입력하는 순서

일반 정리 예시입니다. ① 앞·뒷면이 잘 보이게 촬영 → ② 이름·직함·회사/매장·휴대전화·대표전화·이메일을 각각 옮김 → ③ 원본을 보며 한 글자씩 대조 → ④ 기존 자료에서 이름과 번호/소속을 함께 검색 → ⑤ 새 정보만 추가 → ⑥ 저장 후 다시 열어 확인합니다.

동명이인은 이름만 보고 합치지 않습니다. 같은 사람의 직함·번호가 바뀐 경우에는 과거 값을 지우기 전에 최신 여부를 확인합니다. 숫자 0/O, 이메일 점·하이픈, 대표번호와 휴대전화 칸이 바뀌지 않았는지 확인합니다. 안 읽히는 글자는 빈칸 또는 확인 필요로 두고 추측하지 않습니다.

확인 질문: ‘이 명함은 기존 연락처의 새 직함/번호인가요, 다른 분인가요? 어느 파일에 넣을까요?’
완료 기준: 업로드 자체가 아니라 항목 대조·중복 판단·저장까지 확인. 원본 명함과 실데이터의 접근 범위를 유지합니다.

08카탈로그와 사업계획서

주기: 회사 정보나 시즌 자료가 바뀔 때.

현재 작업은 공유파일의 ‘9.사업계획서(SS,FW)카다로그’에서 연락처·주소·사업자등록증 수정입니다.

1. 수정할 최신 원본과 바꿀 정보의 근거를 확인합니다.

2. 원본을 보존하고 수정본을 구분해 저장합니다.

3. 변경된 연락처·주소·사업자등록증이 서로 일치하는지 확인합니다.

확인 필요: 정확한 대상 파일, 최신 회사 정보, 검수 담당자. 문서 제목만으로 모든 시즌 자료의 수정 완료를 판단하지 않습니다.

출처: 회사 카탈로그 항목 (내부 확인 자료).

문서를 열어서 확인할 곳

실무 수정 예시입니다. 먼저 작업 대상 시즌·판본을 확인합니다. 표지, 마지막 연락처 페이지, 본문 반복 회사 소개, 머리말·꼬리말, 첨부 사업자등록증을 각각 확인하세요. 문서 검색으로 옛 주소·전화번호를 찾아 같은 정보가 여러 곳에 남았는지 봅니다.

1. 최신 정보는 회사가 제공한 사업자등록증·확인된 연락처에서 옮깁니다. 검색 결과나 다른 사업자의 정보를 쓰지 않습니다.

2. 원본 파일을 보존하고 수정본에서 해당 정보만 변경합니다.

3. 문서에 링크가 있으면 표시 글자뿐 아니라 실제 연결 주소도 확인합니다.

4. PDF 등 최종 전달 형식으로 내보낸 뒤 페이지 잘림·이미지 해상도·옛 정보 잔존 여부를 확인합니다.

5. 최종본의 파일명과 저장 위치를 담당자에게 전달하고 이전 판본과 구분합니다.

확인 질문: ‘SS와 FW 둘 다 바꾸나요? 연락처·주소의 기준 자료는 이 파일이 맞나요? 최종 전달은 편집본과 PDF 모두인가요?’
완료 기준: 원본 편집 완료와 최종 전달본 검수 완료를 구분합니다.
